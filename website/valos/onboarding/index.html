Quick start

  1. Visit the public ValhallaOS desk without signing in to inspect its paper-first interface.
  2. Connect a wallet only if you choose; the inspected public desk can display its public address, but connection does not load balances or positions.
  3. Use paper simulation only. It accepts assumed inputs and does not request a signature or execute an order.
  4. Read the product and safety paper and risk disclosure before evaluating the project.

Code-verified capabilities

  • Static public routes include /, /app/, /os/, and /valos/.
  • The public OS includes a wallet-address display and local paper-trade journal.
  • Current public flags leave live trading, rewards payouts, and hive features disabled.
  • Browser auth checks the configured server session; a local-storage flag does not authorize an account.

These are repository observations, not proof of production hosting or external service availability.

Configuration and secret names

Public token metadata lives in website/site-config.js under VALHALLA_SITE.VALOS. The network, mint/contract address, explorer, purchase URL, and X profile begin empty; status is planned-unverified; purchase approval and X profile owner-confirmation are false.

Do not put private keys, provider credentials, mail keys, or database secrets in browser configuration. The existing external Worker secret-name reference is docs/worker-secret-names.example; it lists names only. This website defines no ValOS-token server secret.

The configured X profile is shown only when the owner sets the exact URL and explicitly confirms it. Ask the owner to supply/confirm the URL; do not infer it from a ticker, branch, or prior profile. Share links open a user-controlled X compose screen; the page never requests an X password or posts automatically.

Deployment and rollback

This page ships through the repository website build from website/ to site-build/. The separate Pages publisher and external host settings must be coordinated first. Do not set the Pages readiness gate or dispatch production until an authorized owner approves the release.

For an approved staging release, record the source SHA and release marker, verify exactly one correlated workflow and compare the marker. Roll back with the selected publisher to the last reviewed SHA and verify its marker; do not use DNS changes as a shortcut. See the architecture and launch prerequisites.
