Separate educational experiment

Run the V38 kernel in QEMU

Not the trading application. This is an original, freestanding x86-64 educational kernel. It does not provide trading, wallets, login, or a browser desktop. It is not a production operating system. Run it in an emulator, not on a physical device.

The BIOS ISO was boot-tested on 2026-11-08 under QEMU TCG 10.2.1 with one virtual CPU at 64 MiB and 128 MiB RAM. Both runs produced the required serial markers, three worker messages, and exit status 33. Inspect the actual logs and artifacts.

Run the downloaded ISO

On Debian or Ubuntu, install QEMU. Put the ISO and checksum file in the same directory. Check the ISO checksum before booting.

sudo apt-get update
sudo apt-get install qemu-system-x86
# Download valhalla-v38.iso and SHA256SUMS.txt above.
grep '  valhalla-v38.iso$' SHA256SUMS.txt | sha256sum --check -
qemu-system-x86_64 -accel tcg -m 128M -smp 1 \
  -cdrom valhalla-v38.iso -boot d -display none \
  -serial mon:stdio -no-reboot -no-shutdown

Press Ctrl+A, then X to exit. The guest has no interactive shell. It writes to the serial console and continues scheduling after its demonstration.

Build and test from source

Use an x86-64 Linux host for the native GCC commands below. An ARM host needs an x86_64-elf- cross-toolchain instead. Extract the source ZIP first.

sudo apt-get install build-essential binutils grub-common grub-pc-bin \
  xorriso mtools qemu-system-x86 python3 gdb
cd valhalla-v38
make CROSS= test
make CROSS= run

The test builds build/valhalla-v38.iso, boots the actual ISO, and checks serial output plus QEMU exit status. Missing markers, a panic, or a timeout fail the test. Use make CROSS= debug and connect GDB to :1234 for debugging.

What runs inside

  • Multiboot2 bootstrap and x86-64 long-mode transition.
  • Firmware-map physical-page allocation below 1 GiB, four-level mapping, and a 256 KiB heap.
  • Cooperative round-robin kernel threads and a logger/producer demonstration.
  • Version-38 daemon messages with bounded FIFO mailboxes.

Limits and automation status

Interrupts stay disabled. There is no exception recovery, preemption, SMP, userspace isolation, filesystem, network, or authentication. Heap blocks, page-table pages, and dead thread stacks are not reclaimed. Kernel-resident services trust each other.

A build-and-boot CI template is included in the source, but it is not an active workflow. Enabling it requires workflow-edit permission. This release is backed by the local QEMU checks described above, not a claim of hosted CI or physical-hardware qualification.
